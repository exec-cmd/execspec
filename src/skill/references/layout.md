# Creating spec/ and writing the brief

`xspec init` does the layout. By hand, create in the project root:

```
spec/
  SPEC.md      the project brief
  ROADMAP.md   generated by xspec: Now, Next, History
  changes/     numbered: one piece of work, a feature or a bug
  updates/     numbered: a batch of work; a folder when it has design.md
  analysis/    analyses: other repositories, tools, options
  personal/    the owner's opinions
  notes/       notes, plus glossary.md for project slang and decisions.md
  archive/     closed items, same subfolders
```

1. Add `/spec/` as a line to `.gitignore` (create the file when missing) unless a line already ignores it. The leading slash keeps nested folders such as `src/spec` tracked.
2. Write `spec/SPEC.md` as the stub below.
3. Fill the brief (next section).

```markdown
# <Project name>

## Context

## Audience

## Principles

## Design

## Stack

## Ask first
The agent stops and asks before it does any of these:
- add a dependency
- change a file format or a public interface
- migrate or delete data
- touch secrets, CI or release configuration
```

## Filling the brief

For a `SPEC.md` whose Context is empty (text outside HTML comments counts).

1. **Draft** every section from the README, `AGENTS.md`, the manifest and the code layout. A section the repository does not answer stays a question.
   - Context: what it is and why it exists. Audience: who uses it. Principles: the rules the code already follows, one line each. Design: a few lines, or a link to the design doc. Stack: a table of part, choice and whether the owner knows it. Ask first: the stub's list.
2. **Ask** the owner three or four questions in chat, only about what the repository cannot answer: usually the audience, one or two principles, which stack parts they do not know.
3. **Show** the draft in chat. Write it to `SPEC.md` on the owner's yes.

Done when every section has text and the owner said yes, or the owner declined the draft.
